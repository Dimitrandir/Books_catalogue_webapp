# Family Library — контекст на проекта

Тази система е за картотекиране на семейна библиотека, разпръсната в няколко
къщи/населени места. Django + PostgreSQL уеб апликация, достъпна отвсякъде.

Пълният модел на данните е описан в `docs/DATA_MODEL.md` — прочети го
преди да пишеш каквито и да е models.py промени.

Лог на прогреса между сесии се пази в `docs/SESSIONS.md` — прочети
последния запис в началото на сесия, за да се ориентираш докъде е
стигнало, и добави нов запис в края на сесията (какво е свършено,
текущо състояние, следваща стъпка).

## Технологичен стек

- **Backend**: Django (последна стабилна версия), Python 3.12+
- **База данни**: PostgreSQL
- **Frontend**: Django templates + HTMX (без отделен JS framework, без DRF
  засега — да остане просто; DRF може да се добави по-късно ако потрябва API)
- **Снимки на корици**: Cloudflare R2 (S3-съвместимо) през `django-storages`
  — не се пазят на локалния диск на сървъра
- **АИ разпознаване на корица**: Claude API (vision) — извлича заглавие/
  автор/издателство от снимка на корица
- **Обогатяване на метаданни**: Open Library API / Google Books API — за
  резюме, година, официална корица, ISBN lookup
- **Хостинг**: Render или Railway (безплатен/евтин tier), auto-deploy от GitHub

## Структура на Django проекта

Разделяме на отделни apps по домейн, не всичко в едно:

- `catalog/` — Book, Author, Genre, Publisher, Copy, Location, Condition
- `loans/` — Loan, Person
- `scanner/` — логика за АИ разпознаване на корици + извикване на
  Open Library / Google Books API (отделено от catalog, защото е различен
  тип код — external API calls, не CRUD)

## Модел на данните (накратко)

Виж `docs/DATA_MODEL.md` за пълни детайли. Накратко:

- Справочни модели (dropdown, редактируеми само през Django admin):
  `Author`, `Genre`, `Publisher`, `Location`, `Condition`, `Person`
- `Book` — заглавие, година, резюме, корица (image); M2M към `Author` и
  `Genre`; FK към `Publisher`
- `Copy` — конкретен физически екземпляр: FK към `Book`, FK към `Location`,
  FK към `Condition` (default = "Добро")
- `Loan` — история на заемания: FK към `Copy`, FK към `Person`,
  `date_given`, `date_returned` (nullable)

Важно: `Book` пази метаданните на заглавието (веднъж), `Copy` пази
физическия екземпляр (може да има повече от един `Copy` за една `Book`,
напр. дубликати в различни къщи).

## Ред на разработка (препоръчителен)

1. Django проект setup + Postgres връзка (локално или dev instance)
2. `catalog` app: models + Django admin регистрация на всички модели
   (включително справочните dropdown модели с default за Condition)
3. Migrations + начален seed на "Добро" в Condition
4. Основни изгледи: списък с книги, детайли за книга, търсене/филтриране
   (PostgreSQL full-text search — `SearchVector`/`SearchQuery`)
5. `loans` app: заемане/връщане на книга през UI
6. Upload на снимки на корица + връзка към Cloudflare R2
7. `scanner` app: АИ разпознаване от снимка → предложение за попълване →
   потвърждение от потребителя → Open Library/Google Books обогатяване
8. Деплой на Render/Railway

## Изгледи / екрани

Функционалният обхват на UI-то (визуалният дизайн се решава по-късно, с
помощта на `frontend-design` skill-а — тук фиксираме само какво трябва
да съществува):

1. **Списък с книги** — таблица/грид с корици, търсачка (full-text) +
   филтри по Genre, Author, Publisher, Location, наличност (на място /
   дадена на заем)
2. **Детайли за книга** (`Book`) — показва всички `Copy` записи към нея
   (в кои къщи се намира, брой екземпляри) + история на заемания за всеки
   `Copy`
3. **Форма за добавяне на нова книга** — включва upload на снимка на
   корица + пълния АИ разпознаване flow (снимка → предложени данни от
   Claude API/Open Library → преглед/редакция от потребителя → запис)
4. **Форма за заемане/връщане** — маркира `Copy` като даден на `Person`
   (създава `Loan` с `date_given`) и после връщане (`date_returned`)
5. **Django admin** — управление на всички справочни dropdown модели
   (`Author`, `Genre`, `Publisher`, `Location`, `Condition`, `Person`) —
   идва наготово от Django, не се строи custom UI за това

Начален подход: старт с Django admin за самото добавяне/редакция на
книги (бързо за реализация), custom UI (templates + HTMX) само за
най-често използваните екрани — списък, търсене, заемане/връщане.
Custom форма за добавяне (с АИ разпознаване) идва като следваща стъпка,
не е нужна от самото начало.

## Конвенции при писане на код

- Пиши миграции експлицитно проверени (`makemigrations` + преглед преди
  `migrate`), не разчитай на auto-apply без преглед.
- Всички справочни модели имат `__str__` връщащ `name` полето, за да се
  четат добре в admin и dropdown-и.
- АИ разпознаването и Open Library lookup-ите винаги показват резултата
  за потвърждение от потребителя преди запис — никога auto-save без преглед.
- Секрети (API ключове, R2 credentials, DB парола) — само през `.env`,
  никога hardcoded. Виж `.env.example`.
